### Backup script features (`/opt/wedding-platform/scripts/backup-db.sh`, 9860 bytes)
- Source = live Docker volume (not the stale `/opt/wedding-platform/db/custom.db`)
- Atomic pipeline: temp → integrity → checksum → compress → `gzip -t` → rename (`mv`)

- Permissions: 640 root:aenews

- `Wedding` = top-level tenant entity (line 110)
  - `slug` unique
  - `organizationId` nullable (legacy compat; non-null for new weddings)
  - `commercialStatus` (LEAD/PENDING_PAYMENT/PAID/IN_PRODUCTION/READY/LIVE/COMPLETED/ARCHIVED/CANCELLED)
- `Organization` (line 29) — B2B2C agency model with Stripe customer ID, brand kit, plan, maxWeddings/maxMembers/maxInvitationsPerMonth
- `OrganizationMember` (line 85) — join table with role (ORG_ADMIN/ORG_MEMBER/ORG_VIEWER), unique on (orgId,userId)

### Tenant-scoped entities (all `weddingId NOT NULL`)
- `Guest`, `Table`, `Media`, `Settings`, `Theme`, `MusicTrack`, `EventTimeline`, `CoupleStory`, `GuestSession`, `GuestAccessLog`, `Invitation`, `GuestGroup`, `GuestbookEntry`, `ProgramItem`

### Audit log — already rich
- `AuditLog` (line 685) — weddingId (nullable for platform events), userId, action, details, ipAddress, userAgent, result (SUCCESS/FAILURE), targetUserId, targetResourceId, targetType (WEDDING/USER/ORG/COLLECTION/DEPLOYMENT)
- Indexed on (weddingId, createdAt), (userId), (ipAddress), (targetUserId), (targetResourceId)
- 1,931 rows in production — observability baseline exists.

### Indexes — already comprehensive on hot paths
- `Guest`: 4 composite indexes (status/category/tableId/rsvpAt/checkedIn)
- `Media`: 5 indexes (category/type/semanticRole/slotId/collectionId)
- `AuditLog`: 5 indexes
- `OrganizationMember`: 2 indexes (userId, organizationId+status)

### Hardening gaps identified (for S07)
- ⚠️ SQLite is single-writer (write concurrency bottleneck for high-RSVP scenarios)
- ⚠️ No `@@unique` on `(weddingId, slug)` cross-validation (slug is global unique but weddings in different orgs could theoretically collide if uniqueness relaxed)
- ⚠️ Settings.value is untyped `String` (no JSON validation for structured values like couple_photo)
- ⚠️ No statement_timeout / connection pool (SQLite doesn't need pool; will be PostgreSQL concern)
