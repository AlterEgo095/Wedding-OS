## 1. PRISMA CONFIG

```prisma
generator client { provider = "prisma-client-js" }
datasource db {
  provider = "sqlite"
  url      = env("DATABASE_URL")  // = file:/app/db/custom.db
}
```

### SQLite PRAGMAs enabled (via `src/lib/db.ts`)
- `journal_mode=WAL` (write-ahead logging — concurrent readers + 1 writer)
- `synchronous=NORMAL` (faster commits, safe for WAL)
- `busy_timeout=5000` (5-second lock wait)

### Limitations of SQLite for multi-tenant SaaS
1. **Single-writer bottleneck** — concurrent RSVP submissions serialize on the DB write lock (mitigated by WAL + 5s busy_timeout, but throughput-limited)
2. **No native network access** — file-based, can't be shared across containers without volume mount
3. **No statement-level timeout** — slow queries can stall the lock
4. **No row-level security** — tenant isolation is enforced at app layer (tenantDb extension), not DB
5. **No native JSON type** — `Settings.value` stored as String (JSON-in-string)
6. **Limited FK enforcement** — Prisma emulates via application layer; native FKs require `PRAGMA foreign_keys=ON` per-connection
7. **No streaming replication** — can't have read replicas for scaling reads
8. **No connection pool** — single-process file access; pgbouncer-style pooling N/A
9. **Limited data types** — no TIMESTAMP, ARRAY, JSONB, ENUM, INTERVAL
10. **No native full-text search** — `LIKE` is O(N); needs FTS5 extension
